# Documenting an improvement

Record the date, practice permission, starting workflow, people involved and the intended output.

Explain Kaz's personal contribution, any collaborators and the actual technical decisions. Distinguish software assistance from personal authorship.

Measure comparable work before and after the change, including setup, checking and correction. Record sample size and limitations. Report real observations rather than extrapolating a single best run to an entire practice.

Publish only approved material. Keep client models, personal details and confidential evidence outside this repository.
